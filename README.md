# doubly_linked_list
В этом репозитории содержится реализация кольцевого двусвязного списка с фиктивным элементом

## Использование
Достаточно включить заголовочный файл [dlinked_list.h](dlinked_list.h) в свой исходник и скомпилировать его вместе с [исходником библиотеки](dlinked_list.c). 
```c
#include "dlinked_list.h"
```
```bash
gcc main.c dlinked_list.c
```
Пример кода
```c
#include "dlinked_list.h"

int main() {
  dllist_t list = {};
  printf("Dllist_id = %ld\n", dllist_init(&list, 16)); // 16 - начальный размер внутреннего буфера (см. Реализация)
                                                       // По Dllist_id можно найти созданный список в логах (см. Логирование и отладка)
  
  ssize_t index = dllist_insert(&list, dllist_get_tail(&list), 123);

  dllist_insert(&list, index, 456);

  dllist_insert(&list, dllist_get_prev(&list, index), 1337);

  dllist_insert_before(&list, dllist_get_head(&list), 67);

  dllist_remove(&list, dllist_get_tail(&list));

  dllist_dump(&list, stdout);

  dllist_destruct(&list);
}

```
## Конфигурация
В файле [dlinked_list.h](dlinked_list.h) можно переопределить dllist_elem_t -- тип данных, который будет храниться в списке (по умолчанию int), и DLLIST_MIN_CAP - минимальный размер внутреннего буфера (по умолчанию 6, чтобы список компактно выглядел в графической отладке, но рекомендуется установить больше, например 16, чтобы уменьшить число реаллокаций). Подробнее про внутренний буфер можно прочитать в разделе [Реализация](реализация), про графическую отладку -- в разделе [Логирование и отладка](логирование-и-отладка)
```c
#define dllist_elem_t  int
#define DLLIST_MIN_CAP 6
```
## Обработка ошибок
Во время работы со списком могут возникать ошибки, например нехватка памяти. По умолчанию любая возникшая ошибка логируется и приводит к завершению программы, но есть возможность перехватить ошибку и обработать ее самостоятельно. Для этого необходимо вызвать функцию `void dllist_set_status_handler(dllist_t *dllist, int (*status_handler)(struct dllist_t *dllist))` и передать ей указатель на функцию обработки ошибок. Функция обработки должна обработать статус списка, находящийся в поле `dllist_status status;` структуры. Если функция вернет не нулевое значение, ошибка также будет обработана стандартным обработчиком (логирование и завершение программы).

Перечисление возможных состояний (из файла [dlinked_list.h](dlinked_list.h)):
```c
typedef enum dllist_status {
  DLLIST_OK                         =   1,
  DLLIST_NOT_INITIALIZED            =   0,
  DLLIST_BUF_ALLOC_FAILED           =  -1,
  DLLIST_INVALID_INDEX_OPERATION    =  -2,
  DLLIST_ATTEMPT_TO_REMOVE_ZERO     =  -3,
  DLLIST_ELEM_LOOP_DETECTED         =  -4,
  DLLIST_FREE_LOOP_DETECTED         =  -5,
  DLLIST_NOT_LINKED_NODE_DETECTED   =  -6, 
  DLLIST_ONE_WAY_LINK_DETECTED      =  -7,
  DLLIST_INVALID_LINK_DETECTED      =  -8,
  DLLIST_NOT_FREE_ELEM_IN_FREE_LIST =  -9,
  DLLIST_SIZE_GREATER_CAPACITY      = -10,
} dllist_status;
```
Пример обработчика ошибок:
```c
int custom_status_handler(dllist_t *dllist) {
  if (dllist->status == DLLIST_ATTEMPT_TO_REMOVE_ZERO) {
    puts("Не стоит фиктивный элемент удалять");
  }
  return 1;
}
```
## Логирование и отладка
Логирование можно настроить в файле [dllist_logging.c](dllist_logging.c)
```c
#define DLLIST_LOGGING
#define DLLIST_DEBUG
// #define DLLIST_LOGFILE_TIMESTAMP
// #define DLLIST_LOG_DARK_THEME
// #define DLLIST_TABLE_DUMP
```
По умолчанию логи пишутся в файл `dllist_log.html`. Если раскомментировать `DLLIST_LOGFILE_TIMESTAMP`, файл логов будет создаваться по формату `%H:%M-%d-%m-%Y-log.html`. По умолчанию логируюся все проверки состояния стека, и генерируются графические представления структуры списка(вставляются в лог в svg). Если закомментировать `DLLIST_DEBUG`, логироваться будут только ошибки. Если закомментировать `DLLIST_LOGGING`, логирование полностью отключится. `DLLIST_LOG_DARK_THEME` включает темную тему для логов. `DLLIST_TABLE_DUMP` включает в логи дамп списка в формате таблицы.

Графическое представление списков генерируется с помощью [graphviz](https://graphviz.org/) (Для корректной работы утилита `dot` должна быть доступна в PATH)

## Документация
Взаимодействие с элементами списка происходит через индексы. Каждому элементу, добавленному в список присваивается индекс, но он не обязательно соответствует порядковому номеру элемента в списке (например следующий элемент после индекса 2 не обязательно будет иметь индекс 3). К индексам в некотором смысле можно относиться как к указателям.  
Доступные функции:
```c
// Инициализирует список с размером внутреннего буфера `base_capacity`
ssize_t dllist_init(dllist_t *dllist, ssize_t base_capacity);

// Освобождает выделенную под список память (список становится невалидным,
// его использование будет вызывать ошибку DLLIST_NOT_INITIALIZED)
void dllist_destruct(dllist_t *dllist);

// Вставляет элемент `elem` после элемента `index`. Возвращает добавленный элемент
ssize_t dllist_insert(dllist_t *dllist, ssize_t index, dllist_elem_t elem);

// Удаляет элемент `index`
void dllist_remove(dllist_t *dllist, ssize_t index);

// Возвращает первый элемент списка
ssize_t dllist_get_head(dllist_t *dllist);

// Возвращает последний элемент списка
ssize_t dllist_get_tail(dllist_t *dllist);

// Возвращает значение элемента
dllist_elem_t dllist_get(dllist_t *dllist, ssize_t index);

// Печатает графический дамп списка в out в svg формате
void dllist_dump(dllist_t *dllist, FILE *out);

// Возвращает следующий элемент списка
ssize_t dllist_get_next(dllist_t *dllist, ssize_t index);

// Возвращает предыдущий элемент списка
ssize_t dllist_get_prev(dllist_t *dllist, ssize_t index);

// Вставляет элемент `elem` перед элементом `index`. Возвращает добавленный элемент
ssize_t dllist_insert_before(dllist_t *dllist, ssize_t index, dllist_elem_t elem);

// Задает обработчик ошибок для списка
void dllist_set_status_handler(dllist_t *dllist, int (*status_handler)(struct dllist_t *dllist));

// Печатает дамп списка в out в формате html таблицы
void dllist_dump_to_html_table(dllist_t *dllist, FILE *out);
```
## Реализация
Все элементы списка хранятся в одном массиве. Начальный размер массива выбирается как максимум из значения base_capacity, переданного в dllist_init и значения DLLIST_MIN_CAP. Нулевой элемент является фиктивным элементом, его нельзя удалить, хранение данных в нем не предполагается, через него список зацикливается в кольцо: первый элемент имеет фиктивный как предыдущий, а последний -- как следующий за ним.

Преимущества такого подхода (массив + фиктивный элемент + зацикливание) по сравнению с классической реализацией связного списка (аллокация каждого элемента отдельно, первый и последний элементы ссылаются на NULL):
- Упрощение алгоритма. То, что первый и последний элемент ссылаются на фиктивный, позволяет избавиться от необходимости определять и отдельно реализовывать множество крйних случаев, например при добавлении элемента в конец списка.
- Нет необходимости отдельно хранить начало и конец списка, они будут сами собой оказываться в полях next и prev у фиктивного элемента.
- Все элементы списка лежат в одном массиве, уменьшается вероятность утечки памяти.
- Уменьшается количество аллокаций, что должно приводить к повышению производительности.

Проблема поиска пустой ячейки в массиве для добавления нового элемента решена через связывание всех свободных ячеек в односвязный список. Начало односвязного списка свободных ячеек хранится в поле free головной структуры списка. При добавлении нового элемента, используется пустая ячейка из поля free, вместо нее в поле записывается следующая ячейка из списка свободных элементов. Последний элемент списка свободных ссылается на фиктивный элемент, что позволяет легко определять, когда свободные ячейки закончились. Если необходимо добавить новый элемент, но свободных ячеек нет, происходит реаллокация, длина массива увеличивается в 2 раза.
